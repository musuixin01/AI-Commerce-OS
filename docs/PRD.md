# PRD — 产品需求基线 v2.0

状态：开发设计基线；业务假设需试点验证。范围以 [MVP_SCOPE](MVP_SCOPE.md) 为准；变更须更新需求 ID、验收与 ADR。目标用户为 1–10 人的多店铺团队；首个试点可用玉春农机的真实商品资料，但数据模型不依赖行业。

新增方向：**AI 助手是主操作入口，用户提供素材/目标，AI 制作成果并执行获授权流程，用户确认和处理例外。** 详细交互与执行边界见 [AI_EMPLOYEE_PRODUCT](AI_EMPLOYEE_PRODUCT.md)、[ADR-012](adr/ADR-012-AI-EMPLOYEE-FIRST.md)。

## 北极星和约束

主指标：每件经人工核验并成功交付的平台商品的有效准备时间。配套指标：草稿事实错误率、审核拦截率、客户建议采纳率、发布失败可恢复率、AI 单任务成本。基线值通过试点采集，不预填虚假目标。平台订单/库存仍以原平台为事实源；本系统保留同步快照。

## 用户故事与验收

| ID | 用户故事 | 必须行为 | 验收 |
| --- | --- | --- | --- |
| P-01 | 店主创建组织、空间、邀请运营 | 授权范围显式关联组织/空间/店铺；撤销立即阻断新操作 | 跨组织访问返回拒绝并记审计 |
| P-02 | 运营上传产品资料并生成草稿 | 保留原件/来源、提取结果与人工修改；缺属性标待核验 | 无来源的关键规格不得标“已验证” |
| P-03 | 运营管理 SKU 和平台字段 | 平台字段预检显示缺失、映射版本与目标店铺 | 店铺错误、图片不合格、价格缺失时禁止提交 |
| P-04 | 审批人确认发布 | 展示不可逆影响、价格、图文、SKU 差异和内容摘要 | 批准后改动任何受保护字段使审批失效 |
| P-05 | 系统执行外部发布 | 幂等、限流、处理不确定结果并查询回执 | 同一提交不会产生两个外部商品；不确定结果不盲目重试 |
| P-06 | AI 根据知识与订单自动接待，人工可随时接管 | 支持辅助/规则内自动/人工模式；完整消息和送达状态可见 | 店铺授权+管理员策略启用后才可自动发送；接管阻断待发消息，越权/超时/重复事件不双发 |
| P-07 | 分析员查看运营报告 | 标明来源、区间、货币、数据延迟和缺失 | 缺数据不能编造数值；导出遵守权限 |
| P-08 | 管理员配置 AI 员工和工作流 | 角色、知识、工具、预算、审批策略可版本化 | 执行固定版本，可重放证据但不重复外部写入 |
| P-09 | 外部 AI 客户端通过 MCP 读取授权资源 | 与 Web 共用权限/审计/限流 | 只读能力不可间接触发写工具 |
| P-11 | 团队在 Windows/macOS 桌面、iOS/Android 手机上接续 Web 工作 | 共用组织/店铺/任务，手机拍照、审核与客服，桌面复杂编辑 | 五端均完成登录/撤权/草稿接续/审批；按版本冲突处理，不重复发布 |
| P-10 | 店主掌握费用与风险 | 按组织、工作流、模型显示预估/结算使用量 | 到达预算阈值暂停非关键 AI 任务并提示 |

## 新增核心需求（均待实现，不以现有预览代替）

| ID | 目标 | 验收 |
| --- | --- | --- |
| P-12 | 给图片，AI 制作主图/详情图并填商品字段 | 原件保留、实物结构不静默篡改、字段来源与未知明确、成本可见；同页预览修改确认后才发布 |
| P-13 | 选择已发布商品，AI 读取/诊断/优化 | 实际授权同步快照、修改前后对照、远端冲突检查、确认后更新与回执 |
| P-14 | AI 自动分析数据与店铺经营 | 指标由实际数据计算，来源/口径/时区/延迟明确；缺数据不编造，运营动作受规则与预算限制 |
| P-15 | AI 任务贯通全部业务中心 | 六中心导航、统一会话与成果卡、跨端恢复、取消/重试/确认有确定性状态 |
| P-16 | 可视化 AI 客服现场 | 显示买家/AI/人工、待发/送达/失败，规则和引用可查；人工接管竞态测试通过 |

## 非功能约束

租户数据不得串读；写操作有幂等键、审计 ID 和版本校验。同步 API 响应目标及队列延迟在真实负载基线建立后写入 SLO；初始验收使用可测功能标准，不凭空设可用性百分比。无障碍目标 WCAG 2.2 AA 的适用检查项，设计/实现两层评审。

## 不在首期

全自动批量发布、自动售后承诺/退款、跨平台真实库存写入、抓取竞品私有数据、插件任意代码执行、复杂财务/税务；移动完整工作流画布。后台批量能力后续经风险评估。
