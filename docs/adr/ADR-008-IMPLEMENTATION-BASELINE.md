# ADR-008 — 开发授权与首条可用闭环

日期：2026-09-28
状态：Accepted（内部开发）；生产发布仍需上线验收。

## 背景与授权
用户要求“开始吧 从这里开始到落地再停 ui要简约 大气 直观 美观”。据此开始执行既有五端方案，先交付可运行的商品草稿→分离审批→人工发布包闭环。既有文档和 ADR 保留；本记录确认实施基线，不宣称未验证能力已完成。

## 选择
React/TypeScript Web、Tauri Windows/macOS、Expo iOS/Android，共用 NestJS API。PostgreSQL 是业务事实源。开发用独立样例租户和运营/审批身份；生产模式必须拒绝开发身份。外部平台授权缺失时仅生成明确标识的人工发布包。

## UI 实施基线
浅暖灰背景、白色内容面板、深色文字、低饱和绿色强调；桌面固定侧栏、标题/主操作、指标、商品列表和详情。8px 间距体系，主要面板留白 24px，圆角 12px。移动端优先列表/详情/审批，复杂编辑后续。所有状态用文字表达，表单有标签、键盘焦点、错误与加载反馈。

## API 澄清
创建资源没有前置版本，不要求 If-Match；修改已有资源要求 If-Match。所有业务写入要求 Idempotency-Key。审批绑定商品版本及摘要，不能自审批；修改商品使旧审批失效。未知外部结果不可当作成功。

## 影响与验收
先使用真实 PostgreSQL 验证租户隔离、状态转换、并发冲突、审批失效、幂等与审计。五端构建分别提供证据；没有 Apple 构建资源时不可宣称 macOS/iOS 验收通过。开发环境不等于上线环境。
