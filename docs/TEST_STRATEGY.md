# TEST_STRATEGY — 验证分层与发布门槛

## 已实施测试隔离

后端和浏览器测试分别由 test-runner.ts 创建全新临时数据库并迁移/seed。configure() 在 Node 测试子进程或 COMMERCE_TEST_MODE 下执行严格 URL 保护，不读取演示配置。Playwright 独立端口、不复用现有服务，测试结束清理临时库。保护负例覆盖演示库、生产模式、远端、缺标志和连接参数覆盖；浏览器回归前后比较演示业务表行数和摘要，2026-09-30 的15表一致。


状态：开发设计基线。测试必须验证契约与风险，避免只重复内部实现。

| 层级 | 样例 | 触发 |
| --- | --- | --- |
| 单元 | 商品/SKU 不变量、审批 digest、金额精度、状态转移 | 每次相关提交 |
| 契约 | OpenAPI 客户端、事件 schema、MCP scope、Adapter 标准错误 | 契约变更 |
| 集成 | 数据库事务/outbox、队列重放、对象/向量权限 | CI |
| 端到端 | 上传→知识→草稿→预检→审批→Mock 发布→回执 | 每个里程碑 |
| 故障注入 | 凭据过期、限流、网络超时、重放、平台已受理未回执 | 发布前 |
| 安全 | 租户/空间/店铺越权、提示注入、Webhook 伪造、SSRF | CI + 上线前 |
| 可用性 | 八页面关键任务、键盘与移动适配 | UI 里程碑 |
| 原生端 | Windows/macOS 安装升级、iOS/Android 真机、系统授权、弱网/跨端冲突/推送跳转 | 每端发布前 |
| 性能/恢复 | 并发基线、积压、备份恢复 | 上线前 |

全部外部写操作在 Mock 测试环境执行，真实平台仅经授权沙箱和明确测试店。关键阻断条件：跨租户访问、未授权调用、双发商品、审批绕过、密钥泄露、审计断链、恢复演练失败。无法自动验证平台审核通过的场景须记录人工测试证据。每个任务写可执行验收，与 TASKS 关联。
