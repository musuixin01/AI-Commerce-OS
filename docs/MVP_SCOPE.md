# MVP_SCOPE — 可开工范围与门槛

状态：开发设计基线。目标 MVP 主闭环升级为：**图片输入→AI 商品制作/填字段→成果确认→授权发布；已发布商品优化、可视自动客服和店铺分析按 E3–E5 接续**。现有 0.1 手工审批/导出属于基座预览，不等于目标 MVP 完成；切片见 [AI_EMPLOYEE_PRODUCT](AI_EMPLOYEE_PRODUCT.md)。平台真实发布属于有条件里程碑；试点未获官方写权限时用授权店铺的手工发布包导出与回填回执，不能称其为自动发布。发布代码接口可对 Mock Adapter 开发验证。

## 平台范围

Web、Windows/macOS 安装版、iOS/Android App 均属正式目标。第一批五端打通登录/状态与文件上传探针，再交付草稿/审批最小路径；移动复杂画布与批量编辑后续迭代。五端完成需对应原生设备/安装包证据，不能以响应式网页代替。方案见 [CROSS_PLATFORM_ARCHITECTURE](CROSS_PLATFORM_ARCHITECTURE.md)。

## MVP 切片

| 里程碑 | 可交付结果 | 依赖与验收 |
| --- | --- | --- |
| V0 基座 | 组织/空间/店铺逻辑、身份、授权、审计、API 契约、样例数据 | 租户隔离负例、撤权、审计链通过 |
| V1 知识/AI | 上传、解析预览、版本发布、权限检索；一个 AI 核心、商品/客服两种员工配置 | 来源关联和拒答行为可测 |
| V2 商品 | Product/SKU 草稿、平台映射、预检、版本绑定审批 | 禁止失效审批和跨店铺提交 |
| V3 工作流/工具 | 事件触发、串行/条件/审批节点、暂停恢复、预算与幂等 | 故障注入后可恢复，不重复副作用 |
| V4 对外能力 | 只读 MCP 工具：查询授权商品草稿/工作流运行状态；写入工具仍在内部 | scope、撤权、审计、流量限制负例通过 |
| V5 平台路径 | Mock 平台端到端；如真实官方权限获批准，首个平台试点发布；否则人工发布包 | 真实回执或人工回填标清来源，不虚报自动发布 |

客服目标支持辅助与规则内自动接待及人工接管，详见 ADR-012。先在 Mock 渠道验证实际消息状态和接管竞态；真实自动发送依赖独立消息读取/发送能力及店铺策略授权，不能把内部建议页面认作自动客服。市场分析 MVP 仅对已授权店铺的样例或导入数据生成带口径报告，不承诺平台实时数据。多租户边界从 TASKS 的 M0（此表 V0）落地；账单/支付和自助订阅后续迭代。

本表 V0–V5 是业务切片，TASKS 的 M0/M1 为执行阶段，避免二者编号混用。

## 验收样例

- 真实样例：农机配件包含安装位置和适配机型；系统缺证据时标记待核验，运营修正后可形成 SKU 与发布包。
- 租户 A 的用户使用 A 的 API/MCP/知识查询不能访问 B；撤销成员或店铺授权后新请求立即失败。
- 同一个审批跨两个不同内容摘要或目标店铺不能复用；连接器超时进入 UNKNOWN，查单核对后才能决定补发。
- AI 的商品属性和客服建议可追到原始资料及版本；未知参数返回“待确认”。
- 人工发布包导出只包含已审批字段；回填外部 ID 时需要有权限的人记录证据。

## 三类门槛

**开发门槛**：用户确认此设计基线；指定试点组织/商品样例和首个平台意向，选择代码仓库和部署环境。开发 Mock 与纯内部功能不依赖平台批准。

**真实集成门槛**：官方应用身份、店铺授权、接口 scope/沙箱/审核规则、回调和费用证据，记录在 PLATFORM_FEASIBILITY；缺任一项不打开真实写入。

**上线门槛**：权限与隔离、安全、备份恢复、审计、成本告警、端到端试点通过；由责任人批准发布。清单见 [TEST_STRATEGY](TEST_STRATEGY.md)。
